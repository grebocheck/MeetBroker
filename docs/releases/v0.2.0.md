# MeetBroker v0.2.0

MeetBroker v0.2.0 is the release-hardening update: the product keeps its
Persona-inspired identity while gaining a smaller runtime topology, stronger
operational controls, wider automated coverage, and clearer domain boundaries.

## Highlights

- Nginx now builds and serves the React SPA directly; the runtime consists of
  PostgreSQL, API, notification worker, and Nginx.
- DEMO and production use one `compose.yaml`, with fail-fast production
  configuration validation and a guard against accidental demo seeding.
- The former 1,642-line booking service is replaced by focused query, create,
  update, invitation, cancellation, attendee, media, and open-event services.
- Admin read models, room availability, and room media are isolated behind
  their own service boundaries.
- Notification operations now include worker heartbeat, stalled-job reclaim,
  retry limits, an audited admin delivery console, and richer localized
  Telegram messages.
- Search and pagination cover open events and high-volume admin lists, backed
  by PostgreSQL indexes and literal wildcard handling.
- Containers run without root and use read-only root filesystems, dropped
  capabilities, and `no-new-privileges`.
- Backup and guarded restore cover both PostgreSQL and persistent uploads.

## Schedule interpretation

The room schedule intentionally shows the selected day plus the next six
consecutive days rather than a strict Monday–Sunday calendar week. **Auto**
changes the visible column count from two to seven to fit the viewport without
changing the underlying seven-day range.

- Firefox and WebKit critical-flow smoke
