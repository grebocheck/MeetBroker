# Усунення ризиків із попереднього конкурсного рев’ю

## Запит 095 — зіставлення з минулим звітом

> Перевірити, чи MeetBroker не повторює типових помилок, зафіксованих у
> звіті минулого конкурсу.

### Результат

- попередній звіт зіставлено з кодом, документацією, тестами та Git-історією
  MeetBroker;
- підтверджено, що deployment-інструкції відповідають реальному migration і
  optional seed flow;
- підтверджено повноту i18n-ключів, очищення польових помилок і серверні
  часові інваріанти;
- виявлено статичний `document.title`, суперечливе твердження про готовність
  S3-переходу, подальше зростання `BookingsService` та відсутність
  автоматичного контролю нових commit subjects.

Код у межах аудиту не змінювався.

## Запит 096 — закриття виявлених проблем і ризиків

> Зайнятися наявними проблемами та ризиками.

### Рішення

- назва вкладки браузера визначається маршрутом, станом акаунта й активною
  мовою; для loading state зберігається короткий бренд;
- route metadata винесено в окремий модуль, а browser regression перевіряє
  заголовок кожної критичної сторінки;
- `PROJECT_PLAN.md` більше не називає S3-перехід готовою можливістю:
  `StorageAdapter` явно позначено наступним архітектурним інкрементом;
- з `BookingsService` виділено `BookingAttendeesService`: він відповідає за
  стабільне advisory locking, пошук перетинів і вибір допустимих учасників;
- новий booking boundary покрито unit-тестами для порядку lock, empty fast
  path, структурованого конфлікту та participant projection;
- додано `CONTRIBUTING.md` і CI-перевірку Conventional Commit subjects лише
  для нових pull request, без переписування публічної історії.

### Перевірки

- локалізовані document titles: 10 unit-перевірок;
- attendee coordination: 4 unit-перевірки;
- повний результат: API 51/51 і web 61/61 unit-тестів;
- ESLint, Prettier, API/web typecheck і production build;
- Docker Compose health, повний smoke та 19/19 Playwright-сценаріїв;
- browser regression пройшов для 1440, 1024, 768 і 390 px;
- зовнішній notification worker не запускався під час тесту, щоб тестові
  outbox-події не надсилалися в реальні канали.
