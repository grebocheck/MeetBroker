## Запит 003 — гнучкий доступ і корпоративна перевірка

> Не створювати окрему роль обмеженого користувача. Обмеження мають бути
> гнучкими й, можливо, автоматично тимчасовими. Потрібна ознака
> підтвердженого користувача та можливість адміністратора верифікувати його,
> щоб стороння людина не отримала доступ до корпоративної системи.

### Результат

Розділено автентифікацію, підтвердження email, корпоративне схвалення, роль і
capability-based обмеження. Тимчасові заборони мають необов'язкову дату
завершення і припиняють діяти автоматично. Несхвалені користувачі не бачать
внутрішній календар та імена співробітників.

## Запит 012 — виразніша дизайн-система з натхненням Persona 3 Reload

> Поточний дизайн усе ще виглядає слабко; покращити композицію і шрифти,

- від референсу взято не конкретні екрани чи assets, а принципи: образ

  акцентом поточного часу;
- навігація, календар, вхід, події, профіль і адміністрування перевірені в

## Запит 018 — фото кімнат і критичне падіння booking dialog

> Керування кімнатами зосередити в адмініструванні, дозволити додавати фото
> та зробити стильову заглушку. Виправити зникнення інтерфейсу після кліку
> на вільну клітинку календаря.

### Результат

- встановлено точну причину падіння: controller повертав невирішений
  `Promise` у полі `users`, через що booking dialog викликав `.filter()` не
  на масиві й React демонтував увесь root;
- controller тепер очікує результат сервісу, а dialog додатково захищений
  від некоректної відповіді та дозволяє створити бронювання без запрошень,
  якщо список колег тимчасово недоступний;
- додано міграцію `image_path`, захищені admin endpoints для завантаження,
  заміни й видалення фото кімнати;
- зображення перевіряється через Sharp, кадрується до `1600×900`,
  оптимізується у WebP, а попередній файл видаляється;
- створено спільний `RoomVisual`: реальне фото або синя діагональна
  заглушка з монограмою та рожевим сигналом використовуються в календарі
  й адміністративному списку;
- додавання кімнати разом із фото, заміна та видалення наявного фото
  доступні у вкладці `Адміністрування → Кімнати`;
- smoke перевіряє resolved-масив колег і повний lifecycle фото
  upload → API response → delete → placeholder; browser test підтвердив
  відкриття booking modal без помилок у console.
