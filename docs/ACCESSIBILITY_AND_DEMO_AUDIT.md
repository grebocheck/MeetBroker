# Accessibility та конкурсно-демонстраційний аудит

Дата проходу: **31 липня 2026 року**

## Автоматизований accessibility gate

Playwright запускає `e2e/accessibility.spec.ts` на desktop-wide:

- axe-core перевіряє WCAG 2.0/2.1 A та AA на всіх семи authenticated routes;
- critical і serious violations блокують CI;
- окремо сканується booking modal;
- перевіряється skip-link і передача фокуса до `main`;
- на всіх основних viewport-проєктах уже перевіряються overflow і обрізані
  інтерактивні елементи.

Автоматичний сканер не доводить повної відповідності WCAG. Контраст складних
зображень, логічність текстів, якість локалізації та зручність просторової
навігації залишаються предметом ручної перевірки.

## Ручний keyboard і screen-reader smoke

- [x] На першому `Tab` з'являється skip-link.
- [x] Пункти sidebar мають видимий focus state.
- [x] Theme та language controls доступні клавіатурою.
- [x] Modal/drawer оголошуються як dialog і мають accessible name.
- [x] Після відкриття modal фон стає неінтерактивним.
- [x] `Escape` закриває overlay там, де дія не є незворотною.
- [x] Поля мають label; validation state пов'язаний з повідомленням.
- [x] Icon-only controls мають `aria-label` або доступну назву.
- [x] Поточні стани tabs/toggles передаються через `aria-selected` /
      `aria-pressed`.
- [x] Збільшення браузера до 200% не створює горизонтального overflow у
      головному документі; складна calendar grid використовує адаптивний режим.

## Відомі межі аудиту

- Email і Telegram мають зовнішню інфраструктуру; CI перевіряє формування,
  чергу, idempotency та eligibility, а реальну доставку слід перевіряти окремим
  opt-in тестом, щоб не створювати спам.
- Axe не оцінює суб'єктивну зрозумілість Persona-inspired композиції.
- Gamepad/spatial navigation є прогресивним покращенням, а не конкурсною
  acceptance-вимогою; keyboard spatial flow зафіксовано браузерним тестом,
  а фізичний gamepad усе ще потребує ручної перевірки.
